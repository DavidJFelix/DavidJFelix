# monicandavid.com — 2026-09-10 progress

## Session summary

Laid the groundwork for signing in with Google: the D1 user schema, the session-token contract, and
a gated `/admin` route, with the sign-in flow itself deliberately left for a later session.

## Work completed

- Dependencies: `drizzle-orm` + `drizzle-kit`, `jose` (HS256 JWT), `vitest-browser-svelte` +
  `@vitest/browser-playwright` (component tests in real Chromium), `fast-check` (property tests).
  Playwright was already wired.
- `src/lib/server/db/schema.ts`: `users` (`id`, `full_name`) and `authentications` (`id`,
  `provider`, `provider_id`, `user_id` -> `users.id`, unique on provider + provider id). Ids are
  `user_` / `authn_` plus a UUID v7 in Crockford base32 (`ids.ts`), so they sort by creation time.
  `mise run db:generate` writes migrations into `drizzle/`; the initial one is committed.
- `src/lib/server/session.ts`: `signSession` / `verifySession` -- three claims (`sub`, `iat`,
  `exp`), signature checked against `SESSION_SECRET`, issued-at must have passed, expiry must not.
- `src/hooks.server.ts` refuses every request under `/admin` (pages, `__data.json`, future
  endpoints) without a valid `session` cookie; `/admin` is an empty page with a server load so
  client-side navigation cannot bypass the hook.
- Tests: vitest on the token contract and the schema shape; Playwright on `/admin` over HTTP (the
  local `wrangler dev` boot gets a throwaway `SESSION_SECRET` via `--var`); a first browser-mode
  component test on the theme toggle.

## Decisions

- **Provider id is Google's `sub` claim**, not the email: it is the only identifier Google
  guarantees stable for an account.
- **`authentications.user_id` cascades on user delete** so a removed user leaves no orphaned
  identities.
- **Missing `SESSION_SECRET` is a 500, not a 401**: a misconfigured deployment should look broken to
  the operator, not merely signed-out. No cookie is still a plain 401, checked first.
- **The D1 binding is not in `wrangler.toml` yet.** `wrangler deploy` (and the preview upload)
  reject a binding to a database that does not exist in the account, and creating one needs
  Cloudflare credentials this session does not have. The block is committed commented out with the
  two steps to enable it.
- **No signing route, no login page** -- per the brief. `signSession` exists because the tests need
  it and the sign-in flow will.

## Next steps

- Human: `wrangler d1 create monicandavid-com`, paste the id into `wrangler.toml`, uncomment the
  binding, `wrangler d1 migrations apply monicandavid-com`; `wrangler secret put SESSION_SECRET`.
- Google OpenID Connect sign-in: the callback upserts an `authentications` row (and a `users` row on
  first sign-in), signs a session, sets the `session` cookie (`HttpOnly; Secure; SameSite=Lax`).
- Turn the hook's 401 into a redirect to the sign-in page once one exists.
- Consider passing the preview worker's `SESSION_SECRET` to the e2e job as `E2E_SESSION_SECRET` so
  the signed cases run against previews too (today they run only on the local boot).
