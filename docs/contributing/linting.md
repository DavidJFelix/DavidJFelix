# Linting

Oxlint is the primary linter (root `.oxlintrc.json`); Biome runs alongside it with a pruned rule
list covering only what oxlint cannot check -- CSS lint rules and a handful of JS rules with no
oxlint equivalent. The split was proven rule-by-rule during the migration by a lint-parity kit (one
violating fixture per previously-active Biome rule, asserted against the engine that took it over);
the kit was removed once every fixture passed, and lives in git history on the migration PR if a
future oxlint/Biome bump needs to re-verify coverage.

Fix findings, don't silence them. Don't disable a lint rule or exclude files to make a finding
disappear -- fix the actual issue. Two shortcuts are specifically banned:

- **Per-app Biome or oxlint overrides that turn rules off.** The only sanctioned exceptions live
  centrally, each carrying a comment saying why the rule cannot apply here: the root
  `.oxlintrc.json` turns `typescript/triple-slash-reference` off for `*.d.ts` files (generated by
  frameworks), `react/react-in-jsx-scope` off everywhere (every app compiles with the automatic JSX
  runtime, and oxlint has no `settings.react.runtime` to detect it), and
  `unicorn/no-negated-condition` off as an exact duplicate of the eslint core rule the pedantic
  category already enables; the root `biome.jsonc` scopes its formatter to `.astro`/`.svelte`. Do
  not add per-app variants of either config to dodge a finding.
- **Excluding files to dodge a real finding.** e.g. don't add `!**/*.svg` to skip
  `noSvgWithoutTitle` -- give the SVG a `<title>` or `role="img"` + `aria-label` instead (see any
  `apps/*/public/favicon.svg`).

A single-line `// oxlint-disable-next-line <rule> -- <why>` is the one escape hatch, and only for a
finding you can prove is wrong -- almost always a module the resolver cannot follow, where another
checker already enforces the real contract. Name the rule, never a whole file or block, and say in
the comment what makes the finding false and what does enforce it. Existing uses:
`apps/*/astro.config.mjs` (adapter default exports behind conditional exports) and
`apps/revision.city/src/diffs/components/worker-pool-context.tsx` (Vite's `?worker` suffix, enforced
by `vite/client`'s ambient module declaration). Prefer pinning the tool back if a linter bump makes
a rule newly wrong across many files -- the escape hatch is for one-offs.

Which linter owns which file type is defined in [tooling-standard.md](tooling-standard.md). Spelling
findings have their own ladder -- see [spelling.md](spelling.md).
