# 2026-08-02 progress

Planned, then executed in the same session after David chose the nested-workspace shape and full
scope (CI + affected CD).

## Planning

- Before the theme extraction, all twelve apps shared zero code, so the per-app path filters were an
  honest encoding. The extraction is the flip: `packages/theme/**` in 27 workflow files, a
  hand-added install step in every consumer, and a new `ci-theme.yml`.
- Depot docs verified: Depot CI supports `workflow_call`; Depot Cache supports Turborepo natively
  and is described as built into Depot CI with no configuration.
- Turborepo supports bun workspaces and the text `bun.lock` already in use; `turbo prune` has known
  rough edges with bun but is out of scope (no Docker pruning here).
- David challenged the claim that this must reverse the no-root-workspace rule. Correct: turbo does
  not require its workspace root to be the git root. The one real constraint is that
  `globalDependencies`/`inputs` globs cannot reach outside the workspace root, so the nested shape
  must pull the shared lint configs in with it. Both shapes went into the plan as a decision; David
  picked nested.

## Execution

Order: move -> workspace -> turbo -> hook -> CI -> CD -> docs. Findings worth keeping:

- **`.turbo/` had to be gitignored before caching worked.** Turbo writes `.turbo/turbo-<task>.log`
  inside each package, and since the directory was untracked-but-not-ignored it landed in the task's
  own input hash -- every run invalidated the next. Symptom was maddening: dry-run hashes identical,
  real runs 5/13 cache misses. Diffing two `--summarize` run summaries named the file directly.
- **Biome needed `vcs.root: "../.."`.** With the config at the workspace root and the git checkout
  two levels up, `useIgnoreFile` could not find `.gitignore` and every lint failed.
- **turbo needs `packageManager` in package.json** or it refuses to resolve a bun workspace.
- **`smoke` was invisible to turbo** -- it existed only as a mise task running
  `bun bin/smoke-local.ts` in 11 apps. Added as a package.json script (`cache: false` in turbo.json)
  with the mise task delegating to it, matching the repo's "tasks delegate to package.json scripts"
  convention.
- **djf.io's `test` script ran unit + e2e**, unlike its 11 siblings, so `turbo run test` tried to
  boot Playwright against an app that had never been built. Normalized to the sibling convention.
- **Root install does run workspace `prepare` scripts** -- verified by deleting a generated
  `styled-system/` and reinstalling. That is what lets the deploy matrix drop the explicit
  `panda codegen` step the per-app workflows carried.
- **Every app has per-app Sentry/PostHog variables** (`SENTRY_DSN_<APP>`, `POSTHOG_KEY_<APP>`), so
  the deploy matrix resolves them by name via `vars[format(...)]` with the suffix in the registry.
  This is the piece most likely to behave differently on Depot -- flagged in the plan.

Numbers: 64/64 tasks cached in 209ms warm (vs ~1m35s cold); a `packages/theme` edit invalidates the
theme plus exactly its 8 consumers; 45 workflow files -> 15.
