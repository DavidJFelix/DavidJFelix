# 2026-07-29: CSS sizing token enforcement turned on

Added scope item 4 and landed its first half: both styling systems now gate raw length values
(px/em/rem/ex and friends); what remains is the burn-down and the severity promotion.

## What landed

- `strictTokens: true` in all nine Panda apps' `panda.config.ts`. Token-bound properties now only
  accept theme tokens, `var(--x)`, or the explicit `[...]` escape hatch -- enforced by TypeScript
  via the generated `styled-system` types, no linter involved.
- Every pre-existing raw value was mechanically wrapped in an escape hatch, chosen specifically to
  keep the emitted CSS byte-identical (no token substitutions, e.g. `'600'` became `'[600]'`, not
  `'semibold'`). These brackets are the burn-down list: 401 total -- revision.city 192,
  forzamonica.com 91, alchemy-state-viewer 90 (plus 19 `m: 0` to `'0'` token conversions), djf.io
  17, calendar-visualizer 8, and one each in monicandavid.com, onvibes.org, pkg.dog, and
  startchi.com.
- `oxlint-tailwindcss` (v1.6.0) wired into the two Tailwind v4 apps (f311x, ravrun) via per-app
  `.oxlintrc.json` files that extend the root config; `tailwindcss/no-arbitrary-value` at `warn`.
  Four findings today, listed in plan item 4; promote to `error` once they are fixed.
- All nine Panda apps typecheck clean; both Tailwind apps lint clean (warnings only).

## Decisions

- **Oxc-only direction**: Biome gained no new responsibilities. The Panda gate is type-level; the
  Tailwind gate rides oxlint's `jsPlugins` (alpha, but the plugin spawns no subprocesses, so it
  avoids the fork-ENOMEM failure mode found when running `@pandacss/eslint-plugin` under the same
  engine).
- **`@pandacss/eslint-plugin` under oxlint: rejected.** It works (verified end to end), but it
  bundles `panda.config.ts` with esbuild at lint time, and oxlint's plugin host reserves ~28 GB of
  virtual address space -- child-process spawns fail with ENOMEM on hosts with default overcommit
  and modest RAM. Not worth babysitting.
- **daily-ui stays out.** Its Tailwind-v0-era exercises have no package manifests and are outside
  the check standard (see item 5).

## Follow-up (tracked in plan item 4)

- Replace escape hatches with real tokens per app, extending app themes where needed.
- Fix the four Tailwind arbitrary-value warnings, then set `no-arbitrary-value` to `error`.
