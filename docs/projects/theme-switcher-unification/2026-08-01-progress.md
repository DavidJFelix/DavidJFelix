## Decisions made

- `packages/` is a new top level for shared code apps consume -- deliberately not `workspaces/`,
  which quarantines trees that must not collide with the parent repo.
- One package with subpath exports rather than core/react/astro sibling packages: external `file:`
  consumers cannot resolve `workspace:*` internal deps, and 300 lines of source does not justify a
  build step or a workspace.
- Raw TS source ships as-is: every consumer bundles with Vite. No `ssr.noExternal` was needed
  anywhere (verified by building all eight apps and running the theme e2e suites).
- The inline scripts now carry the source comments of the typed bootstrap (String(fn) of the
  transformed module); f311x has shipped this way via ScriptOnce since PR 1, so the Astro apps
  simply join the status quo.

## Environment notes (for future sessions)

- Two pnpm versions exist in web containers: a standalone pnpm 10 on PATH and mise's pinned pnpm 11.
  Lockfiles must be (re)generated with `mise exec -- pnpm` -- pnpm 10 writes entries the repo's
  release-age supply-chain policy rejects, which `--frozen-lockfile` then fails in CI.
- `mise exec -- pnpm run <script>` trips the no-TTY module-purge prompt; invoke tool binaries
  directly (`node_modules/.bin/<tool>`) or set `CI=true`.
- onvibes.org's playwright webServer needs the Flue worker build (`flue build --target cloudflare`
  plus `bin/patch-flue-wrangler.ts`), not just `astro build`.
