# 2026-11

## 2026-11-16

### build(web-apps): run each app's typecheck after its build

Each app's `mise run check` ran typecheck at the same time as build. The build writes files that
typecheck reads, so the two could race, as turbo already notes for the root check. Typecheck now
runs after lint, format, test and build finish, in all 12 apps. The header line and the stale test
task description in the app `mise.toml` files now say what is true.

### ci(web-apps): run one production deploy per worker at a time

The production deploy job now has a job-level concurrency group keyed on the worker name, with
`cancel-in-progress: false`. When several merges land close together, a second deploy of one worker
waits for the first to finish instead of running beside it, so the D1 migrations step never runs
twice at once. Deploys of other workers still run side by side.

### docs(revision.city): say symbol diff in the plan and the Lezer dictionary notes

The revision.city plan, the cspell config and the Lezer dictionary header now say "symbol diff
engine" and `/api/diffs/symbol-diff`, to match the code after the entity-to-symbol rename.

### feat(revision.city): say when a compare's base branch moved on

A GitHub compare diffs from the merge base, so commits that landed on the base branch later are not
in the diff. When a signed-in visitor opens a three-dot or one-ref compare whose base has such
commits, the sidebar now shows a row such as "main moved on 3 commits since the merge base". The
count is `behind_by` from GitHub's compare answer, read through a new
`/api/diffs/github-compare-status` route. Signed-out visitors, two-dot compares, and pull requests
get no row.

### fix(ci): name the repository for gh in Depot CI workflows

The changelog roll-up failed at `gh pr list` with "no git remotes found". The Depot Code checkout
does not add a github.com remote, so `gh` cannot find the repository from git. The roll-up step and
the `gh pr comment` and `gh pr edit` steps of the two snapshot bots now set `GH_REPO` to the run's
repository.

### fix(revision.city): read a findings list sent as JSON text with prose after it

A chunk review whose `findings` value is JSON text no longer fails when the model adds prose or a
closing Markdown fence after the array, or opens the text with a fence. The parser reads the array
from its `[` to the matching `]` and ignores the rest. This replaces the earlier rule that removed
only trailing braces.

### fix(revision.city): send route templates, not repository paths, to Sentry from the server

The server Sentry SDK now applies the telemetry scrub helper in `beforeSendSpan`, `beforeSend` and
`beforeBreadcrumb`. Request names and the 5xx message title use the route template, such as
`GET /diffs/$path answered 502`. Outgoing calls keep only their origin. Console breadcrumbs keep the
origin of each URL and lose `repository` fields, and wide events give no breadcrumb. The log lines
in Workers Logs and Honeycomb do not change.

### refactor(revision.city): rename symbol extraction and matching from entity to symbol

`extract-entities.ts`, `match-entities.ts` and `entity-signature.ts` are now `extract-symbols.ts`,
`match-symbols.ts` and `symbol-signature.ts`, with their tests. `extractEntities` is
`extractSymbols`, `matchEntities` is `matchSymbols`, and the names, comments and test titles in
these files say symbol. The review tool that reads definitions uses the new names. This is the
second of five rename steps. The behavior does not change.

### refactor(revision.city): rename the symbol diff client, endpoint and hook from entity to symbol

`entity-diff-client.ts`, `entity-diff-endpoint.ts` and `use-entity-diffs.ts` are now
`symbol-diff-client.ts`, `symbol-diff-endpoint.ts` and `use-symbol-diffs.ts`, with their tests.
`streamEntityDiffs`, `handleEntityDiffRequest`, `useEntityDiffs`, `EntityDiffRequest`,
`EntityDiffEntry` and the other names in them say symbol, and so do their uses in the diffs sidebar,
the review page and the Symbols tab test. The route path does not change yet. This is the fourth of
five rename steps. The behavior does not change.

### refactor(revision.city): rename the symbol diff route from entity to symbol

The Symbols tab now sends its batches to `/api/diffs/symbol-diff` in place of
`/api/diffs/entity-diff`. The route file, the client's default endpoint, the paths in the tests and
the generated route tree use the new path. This is the last of five rename steps. A tab that stays
open across the deploy gets a 404 from the Symbols tab until it reloads.

### refactor(revision.city): rename the symbol diff from entity to symbol

`diff-entities.ts` and its test are now `diff-symbols.ts` and `diff-symbols.test.ts`. `diffEntities`
is `diffSymbols`, and `EntityChange`, `EntityChangeType`, `EntityDiff` and `EntityDiffSummary` are
`SymbolChange`, `SymbolChangeType`, `SymbolDiff` and `SymbolDiffSummary`. The coverage gate names
the new file. The comments in these files say symbol. This is the third of five rename steps. The
behavior does not change.

### test(revision.city): hold three more viewer modules to the coverage gate

The coverage gate now also names `constants.ts`, `github-auth.ts` and `gutter-detector.ts` in
`src/diffs/lib`. New tests cover the first batch size for each viewport height, the gutter probe and
its cache, and the sign-in paths that had no test: missing credentials at the callback, a failed or
unreadable user lookup, and an expired session with no refresh token. The thresholds do not change.

## 2026-11-15

### ci(web-apps): probe sign-in and the review webhook after deploy

The production smoke fetched pages only, so a deploy without the sign-in credentials or without the
review Workflow still passed. After the pages pass, the revision.city production smoke now sends two
probes that carry no credential and change nothing: the sign-in config route must report
`configured` true, and an unsigned review webhook delivery must get 401, not 503. The registry in
`bin/plan-affected-apps.ts` has a `probes` list, which only the production deploy entry carries. A
failed probe marks the job red and does not roll back.

### fix(revision.city): make sign-out a POST

The sign-out route now answers only POST, and it refuses a request whose Origin header names another
site. The Sign out button submits a form instead of opening a link. Before, a link on any other site
could sign a visitor out and revoke their GitHub token.

### fix(web-apps): pass the Cloudflare Access service token to the production smoke

The production smoke step from #1070 did not get `CF_ACCESS_CLIENT_ID` and
`CF_ACCESS_CLIENT_SECRET`, so the onvibes.org deploy failed: Access sent the smoke to its login
page. The step now gets the same service token that the preview smoke uses.

### refactor(revision.city): rename the core symbol types from entity to symbol

The Symbols core module `entity.ts` is now `code-symbol.ts`. `CodeEntity` is `CodeSymbol`, and
`EntityKind`, `EntitySpec`, `EntitySpan`, `EntityRange`, `entityProp` and `ResolveEntityNameParams`
now say symbol, to match the glossary. The comments in the module and in the language tables use the
same word. This is the first of five rename steps. The behavior does not change.

## 2026-11-14

### build(revision.city): check the committed worker types at typecheck

The app's typecheck now fails when the committed `worker-configuration.d.ts` is stale: it runs
`wrangler types --check` before `tsc`. A new `mise run types` task regenerates the file after a
wrangler bump or a `wrangler.toml` change. Both commands ignore a local `.dev.vars`, so a laptop and
CI make the same file. The file is regenerated here for the pinned wrangler, which moves the runtime
types to a newer workerd.

### ci(web-apps): smoke each app's production site after its deploy

The production deploy ended at `wrangler deploy`, so nothing fetched the live site, and a broken
deploy showed up first as a visitor report. The registry (`bin/plan-affected-apps.ts`) now has a
production URL for each app that names a custom domain in its `wrangler.toml`. After the deploy, the
deploy job runs `bin/smoke-url.ts` against that URL. Seven apps are checked: davidjfelix.com,
monicandavid.com, onvibes.org, pkg.dog, ravrun, revision.city and startchi.com. revision.city now
smokes `/` and `/diffs`, on previews too. A failed smoke marks the job red and does not roll back.

### docs(contributing): use named arguments past three parameters

The code style guide now says to use named arguments past three parameters, not past two. This
agrees with the lint rule `max-params`, which permits three. The guide applies to the whole repo,
not only to revision.city. No code changes.

### docs(revision.city): add a setup note and a .dev.vars.example

revision.city now has a `README.md` that says how to set up, run and test the app, how to make the
local D1 database, which build-time names it reads, and how the review webhook is signed. A new
`.dev.vars.example` lists the local secret names, without values. The app's `.gitignore` now also
ignores `.dev.vars.<env>` files. The note is a `README.md`, not an `AGENTS.md`, because the review
engine sends the nearest `AGENTS.md` with each model call.

### docs(revision.city): add a glossary for the diff viewer and Symbols

revision.city gets a `CONTEXT.md` with the words of the diff viewer and its Symbols tab, and a row
in `CONTEXT-MAP.md`. The unit of the Symbols tab is a symbol, the word that visitors see; the code
still says entity until a rename that follows in its own PRs. The review engine's words join the
glossary later.

### docs(revision.city): record what telemetry may hold

The revision.city plan now has a "Telemetry and privacy" section. PostHog, Honeycomb and Cloudflare
Workers Logs may hold repository names and file paths. Sentry holds route templates, and no service
holds private code. The section also says which parts of the rule the code does not follow yet.

### feat(revision.city): send route templates, not repository paths, to Sentry from the browser

The browser Sentry SDK now names page loads and route changes by route with the TanStack Router
integration. A new helper turns viewer and share-card paths into `/diffs/$path` and drops the diff
API query and the hash. The `beforeSendSpan` and `beforeSend` hooks apply it to span names, URL
attributes, the request URL and the breadcrumbs. PostHog and Honeycomb keep full paths.

### fix(revision.city): allow zoom on /diffs with 16 px inputs on phones

The diffs pages no longer block pinch zoom. On phones, the URL box, the comment box and the file
tree search box now show 16 px text, so iOS does not zoom the page when you tap one. Desktop sizes
and the other file tree text do not change.

### fix(revision.city): let Enter and Space pick the color mode in the theme menu

In the theme menu of the diff viewer, a keyboard user can Tab to the Auto, Light and Dark buttons,
but Enter and Space did not pick the color mode, because the menu took the key and canceled the
click. The buttons now keep these keys, so the key picks the color mode and the menu stays open. The
look does not change.

### fix(revision.city): read a compare's old side at the merge base

On a GitHub compare where the base branch moved on after the head branch split off, expanded context
and the Symbols tab read the old file at the base tip, but the patch starts at the merge base. They
now read the old file at the merge base for a three-dot or one-ref compare, as a pull request does.
A two-dot compare still reads the base tip.

### fix(revision.city): give decorator and attribute changes a symbol row

In the Symbols tab, a changed decorator or attribute now gets a row on the declaration that it
marks: a Python `@app.route(...)` on its function, a Rust `#[derive(...)]` on its struct, and a
TypeScript `@Component(...)` above `export class` on the class. A changed method decorator or
attribute goes to the method, not to the enclosing class or impl. A decorated declaration now starts
at its first decorator, also in the lines that the reviewers' `read_definition` tool shows.

### fix(revision.city): show a keyboard focus ring on viewer chrome buttons

Keyboard focus on the viewer chrome now shows a 2px outline in the chrome text color of the active
theme. This applies to the icon buttons in the header and the sidebar, and to the Diff Stats and
System Monitor toggles, which removed the outline before. The Delete comment button on a saved
comment now also shows when it has keyboard focus, not only on hover.

### fix(revision.city): log who refused a GitHub token exchange

A failed sign-in token exchange now logs every response header except `Set-Cookie`, and the first
500 characters of a body that is not JSON. The 429s from 2026-11-12 had no headers or body in the
log, so it was not possible to say which layer sent them. A JSON body is never logged, because it
can hold a token. The comment on the retry no longer says that github.com limits by IP address or
that Workers share addresses, because that is not proven.

### fix(revision.city): revoke the GitHub token on sign-out

Sign-out now asks GitHub to revoke the access token of that session before it clears the cookie, so
that access token stops working at sign-out. The revoke is best effort: when GitHub refuses it, is
slow for more than 3 seconds, or cannot be reached, the worker logs the failure with the step
`token revoke`, and the sign-out continues as before.

### refactor(revision.city): delete unused theme wrappers, patch cache and exports

The diffs viewer loses code that nothing used: the `ThemedFile`, `ThemedFileDiff` and
`ThemedSurface` wrappers, the theme selector, the patch cache, the item version helper,
`getGutterSize` and `docsThemeResolver`. Six helpers in `github-auth.ts` are no longer exported,
because only that file uses them. No change for visitors.

### test(revision.city): hold the fully covered viewer and Symbols modules to the coverage gate

The coverage gate now names the 32 modules in `src/diffs/lib` and `src/symbols/lib` that have full
line, statement and function coverage. Before, the gate held only the shared helpers, the client
config and the review engine, so coverage in the viewer and Symbols logic could fall with no signal.
The thresholds do not change.

## 2026-11-13

### feat(revision.city): review again when a user reruns the check

A click on Re-run on the Revision City check run now starts a review. So does a click on Re-run all
checks. The review is the same one that the `Revision City` label starts, at the current head of the
pull request. Each click gets its own Workflow instance from the delivery id, and saved chunk
reviews cover every unchanged chunk. Re-run all checks needs the GitHub App to subscribe to "Check
suite" events.

### fix(djf.io): skip analytics when the PostHog chunk does not load

When the browser cannot load the PostHog SDK chunk, the page now skips analytics. Before, the failed
import was an unhandled rejection that Sentry reported as an error (DJF-IO-2). The chunk fails to
load when a tab stays open across a deploy and asks for a hashed file that is gone, or when the
visitor leaves the page during the fetch.

### fix(revision.city): keep the closed phone file tree out of the focus order

On a phone, the closed file tree now has `visibility: hidden` after its slide ends, so Tab and
screen readers do not reach it. The open tree is a modal dialog: focus moves into it, Escape closes
it, focus goes back to the toggle, and the header and the diff behind it are `inert`. The desktop
sidebar does not change.

### fix(revision.city): report a renamed symbol container once

When the Symbols tab pairs a renamed class or a renamed JSON or YAML key, the members inside it now
pair by identity under the new name. A member that did not change gives no row, and an edited member
gives a `modified` row. Before, a class rename with five untouched methods gave six rows, and a
renamed `devDependencies` key with six keys gave seven.

### test(revision.city): test the Symbols GitHub read signed in and signed out

The Symbols endpoint now has tests for a GitHub read. A signed-out read sends no token and gives a
diff. A signed-in read sends the session token and does not put its files in the cache that all
visitors share. An expired session token is refreshed, and the new session cookie reaches the
browser. The endpoint now takes the app credentials as an option, as the other GitHub endpoints do,
so that the tests can supply them. The old signed-out test could not fail and is gone.

## 2026-11-12

### feat(djf.io): show the hero tagline under a post's title

A blog post's `hero.tagline` frontmatter now renders under the post title. Before this change the
schema accepted the field, but no page used it. On Positivity and On Running drop their taglines,
because each one only repeated the title.

### feat(og): render share cards with Takumi on WebAssembly

The share card renderer in `@davidjfelix/og` now uses Takumi (`@takumi-rs/wasm`) in place of satori
and resvg. Takumi makes the card layout and draws the PNG in one WebAssembly module, which loads on
Cloudflare Workers the same way as the old modules. The cards keep their layout; some text moves by
a few pixels at most. In a local benchmark, a card after the first renders in about 6 ms in place of
about 23 ms. The fonts are now WOFF2 files, because Takumi does not read WOFF. Each Worker upload
grows by about 0.7 MB gzipped. The package tests now compare three cards with committed PNG
snapshots and measure the card layout. Takumi draws text directly to pixels, with no SVG step. So
the `ogSvg` export and the SVG text test that pinned satori's advisory are gone, and so are satori,
`@resvg/resvg-wasm`, and the Renovate rule that held satori at 0.32. The apps' comments no longer
describe how the og package works; its README does.

### fix(revision.city): report C and C++ prototypes, globals and #define

The Symbols tab showed "No symbol changes" when a pull request changed only a C or C++ prototype, a
top-level global or a `#define`. A top-level declaration is now a symbol, of kind `function` when it
has a function declarator and `variable` otherwise, and a `#define` is a symbol of kind `macro`. An
`#include` and a declaration inside a function body still give no row.

### fix(revision.city): mark a symbol diff that was too large to read

A symbol diff for a file over a size limit now carries `skipped: 'too-large'`, and the client keeps
the mark. Before, that result looked the same as a file with no symbol changes. A parser stack
overflow on deeply nested input now also gives the too-large result, so `read_definition` answers
"too large" and the chunk review goes on. The Symbols tab does not show the mark yet.

### fix(revision.city): read the app's installations in one place, 100 per page

The access diagnosis read the app's installations without a page size, so GitHub sent only the
first 30. A visitor whose token sees more installations than that got the install page, not the "not
granted" message and the settings link of the right installation. One shared reader now asks for 100
per page, and the access diagnosis and the pull request list both use it.

### fix(revision.city): pair leftover same-name symbols by likeness

When a file deletes one of several same-name symbols and edits a sibling, the Symbols tab now blames
the right ones. Repeated names (overloads, workflow step keys) that are left over after the content
matches used to pair by position, so the row for the edit went to the deleted sibling. Now each
leftover on the shorter side pairs in order, and the longer side skips the entries that give the
lowest total likeness, scored on the words inside each token. Equal counts still pair in order, and
a group over the read budget keeps the old pairing.

### fix(revision.city): cite diff lines in a finding proof by their text

The finding check now reads that the numbers on the left of the diff piece are labels for the piece,
not file line numbers. A proof quotes a diff line by its text and file path, and gives a line from a
tool result its file path and its "L" number. The saved-result key version goes from 2 to 3, so the
first review of each open pull request after this change pays again for every chunk review.

### fix(revision.city): claim a shape rename only for an identical body

The Symbols tab called two entities a rename when they had the same shape, even when their text was
not related. Now the shape match also needs the same body, without the name. Other pairs go to the
token match, which marks a rename whose body also changed as "body edited". Some pairs that matched
by chance now show as one added and one deleted row.

### fix(revision.city): require a token mode for GitHub file reads

A GitHub file read now must say if it is signed in (with the visitor's token) or anonymous, or the
type check fails. Only an anonymous read uses the cache that all visitors share. Before, the mode
was optional and a read without it went to the shared cache; both callers already set it, so
visitors see no change. The unused fallback to a server token from the process environment is gone.
The file expansion endpoint takes injected `fetch` and app credentials, and has its own tests for
the sign-in gate, the session token, the error status and the refreshed cookie.

### fix(revision.city): tell the reader which files Symbols did not read

The Symbols tab now shows one muted line, such as "2 files not read", when a file was too large to
read or its read failed. The line opens to name each file and its reason, and a Retry button asks
again for the failed files only. When no file changed a symbol but some files were not read, the
empty state says "No symbol changes in the files that were read". A file that the stream did not
answer now becomes an error and does not stay on "Reading" for good. A re-run with a new list of the
same files no longer leaves them in flight, because the effect cleanup now drops the files that are
still loading.

### fix(revision.city): space out pull request list reloads and ask for a new sign-in

The home page's pull request list now reloads on window focus only when the last load started 30
seconds ago or more, so a visitor who switches windows often does not use up GitHub's search rate
limit. When GitHub rejects the visitor's token, the list shows "GitHub rejected your sign-in. Sign
in again." with a sign-in button, in place of a stale list or a general error.

### fix(revision.city): keep the symbol occurrence number as data

Each symbol now carries its path and its occurrence number as separate fields, and the Symbols
matcher groups repeated names by that path. Before, the matcher removed every `#<n>` from the name
with a pattern, so a number that the author wrote was also removed, and two headings that differ
only in that number had the same identity. A heading "Verified on Depot (PR #406)" changed to
"Verified on Depot (PR #407)" now shows one renamed row in place of a modified row. The display
names do not change.

### fix(revision.city): retry a GitHub sign-in that github.com throttles

github.com answered the sign-in's code exchange with 429 three times in a row on 2026-11-12, so the
callback showed "GitHub sign-in failed". github.com limits requests by IP address, and Workers share
their outgoing addresses. The exchange now tries up to three times when GitHub answers 429, logs the
`Retry-After` header, and, if every attempt is throttled, answers 503 with a message that names the
rate limit.

### test(revision.city): run unit tests in the node environment by default

The revision.city unit tests now run in node by default. Before, every test file started a jsdom
browser, and most files did not use it. The file name now picks the environment, through two Vitest
projects: `*.test.tsx` and `*.dom.test.ts` run in jsdom, and the other `*.test.ts` files run in
node. Four `.ts` tests that read browser globals are renamed to `.dom.test.ts`, and the six
`// @vitest-environment node` lines are gone. A new test that reads `window`, `document` or
`navigator` with a plain `.test.ts` name fails at once. A full `bun run test` took about 32 s before
and 16 s after on a 4-core container.

### test(revision.city): assert a refreshed session cookie on the diff and pull request routes

The diff route and the pull request list now each have a test for an expired session token. The test
makes sure that the route sends the refreshed token to GitHub and that the answer gives the new
session cookie to the browser. Before, only the auth helper had this test, so a route that stopped
forwarding the cookie still passed CI.

### test: compare every app's share card with a committed PNG

The Playwright suites of revision.city, startchi.com, ravrun, forzamonica.com, davidjfelix.com,
monicandavid.com, pkg.dog, and djf.io now fetch each share card route and compare the PNG with a
committed baseline, with the same 1% allowance as their page screenshots. revision.city also checks
its pull request and compare cards. djf.io checks its default card and one fixed post, so a new post
does not need a new baseline.

## 2026-11-11

### build(revision.city): deny server-only modules in the client build

The client build now fails when a server-only module is still in a browser chunk after tree shaking.
The Vite config gives the TanStack Start import protection a list of these modules: the review
engine, the symbol grammar modules, the diff endpoints and file servers, the pull request modules,
and the GitHub sign-in module. Before this change, only the habit of each author kept this code out
of the browser. No module moves, and visitors see no change.

### ci(web-apps): preview and deploy every app when a change affects no app

The preview and deploy workflows start on changes to repo-root tooling, such as `bin/`, the
composite actions and the tool pins. Turbo cannot see those files, so it found no affected app, and
the workflows previewed and deployed nothing. A tooling change then reached each app only with that
app's next change, and a break looked like that change's fault. Now, when a change affects no app,
the plan takes every app in the shared matrix: the preview tests the tooling change on every app,
and the deploy on main ships every app built with it.

### docs(repo): allow emojis that carry status or feedback

The emoji rule in `AGENTS.md` now says what it was written to stop: emojis as flavor on headings,
titles, commit messages and sentences. An emoji that is a status icon, or that gives feedback on a
result, is allowed. The pass and fail marks in the preview comment are the example.

### docs(repo): describe the Revision City review and refresh its project docs

`CONTRIBUTING.md` now names the Revision City review: when it runs, the `Revision City` check, and
how to clear the check. It also says that Warden runs only on its label. The revision.city Reviews
plan describes the summary comment and the answer tool. The project index now agrees with the
label-only Warden, the Review Consolidation plan gets a note that it is superseded in part, and the
context map no longer links the root `docs/adr/` folder, which does not exist.

### feat(revision.city): upload hidden client source maps to Sentry

When the Sentry token, org and project are all set, the client build makes hidden source maps,
uploads them to Sentry with `@sentry/vite-plugin` and then deletes them, so the asset server never
serves them. Sentry can then show the original source lines for a client error. A build without one
of the three variables is the same as before.

### feat(revision.city): log the verdict of each finding check

Each finding that the review would post goes through a check, and until now the result of that check
was not logged. The check now logs one `finding check` event per such finding, with the reviewer,
the file path, the finding number, the severity and the verdict: `confirmed`, `rejected`, `failed`,
`unparsed` or `over-limit`. A count of verdicts by reviewer shows if the check rejects more findings
from one reviewer. The prompts do not change, so saved chunk reviews stay valid.

### feat(revision.city): give review telemetry a run id and the step attempt

Each `review run` and `model call` event now has `runId`, the Workflow instance id, so the events of
one run share one value. The run events after the start also have the check run id. Each model call
event has the review step, the step attempt (counted from 1) and the chunk number. Thus the cost of
a run with retried steps is the sum of its model calls. The three warnings in the run also have the
run fields.

### feat(revision.city): log one wide event for each webhook delivery

The GitHub App webhook now logs one `webhook delivery` event for each delivery with a valid
signature. The event has the delivery id, the GitHub event and action, the decision (the status in
the response, or `error` when the handler fails) and the reason. For a review that starts or that
already exists, it also has the Workflow instance id of the review as `runId`. The responses do not
change, and deliveries with no secret or a bad signature log nothing.

### fix(revision.city): read a bare findings list and fail on loose findings

A review answer can be a JSON array with no object around it, alone or in a Markdown fence after
some prose. That array now counts as the findings list. Before, the parser kept only the first
finding of the array and saved the short result with no failure. Two or more findings with no list
around them, for example an array inside prose with no fence, now give a failed chunk review. Its
reason is "No findings list: N findings without a list around them". The engine does not save a
failed chunk review, so the next run asks the model again. One finding with no list still counts as
a list of one.

### fix(revision.city): skip diffs with very long lines and bound a chunk's characters

The review engine bounded a chunk by lines only, so a generated file of one long line went to each
reviewer as one huge chunk. A file with a diff line longer than 5,000 characters now shows under
"Not reviewed" with its own reason, and a chunk also stops at 40,000 characters. Normal code and
prose get the same chunks as before.

### fix(revision.city): name the URL field, comment box, submit button and sidebar tabs

Screen readers now hear a name for the diff URL field ("Diff URL"), the comment box ("Comment") and
the icon-only comment submit button ("Submit"). The sidebar tabs and the header menu button groups
now tell which item is selected. A saved comment is now read as its author and message. While the
"Please enter a valid URL" popover shows, a scroll event no longer renders the URL form again if the
field did not move. Nothing changes on screen. Vitest now transforms `@pierre/icons`, so unit tests

## 2026-11-10

### chore(revision.city): raise the Worker subrequest limit for review runs

Cloudflare lets a Workflow instance make 10,000 subrequests by default. A review run at its size
limits can make about 115,000: 450 chunk reviews of at most 254 subrequests each, from OpenRouter
requests with their retries, blob reads and D1 queries. After the limit each later call fails, so
the run cannot report the failure and its check run stays in progress. `wrangler.toml` now sets
`[limits]` to 150,000 subrequests, and its comment gives the arithmetic. The limit applies to the
whole Worker, so the viewer routes get it too.

### fix(ci): match the preview comment by bot author

The sticky preview comment script now keeps and edits only a comment that a bot wrote and that
starts with the app's marker. Before this change it matched any comment that contained the marker,
so a person's comment with the marker could become the edited comment, and the bot deleted a
person's comment that quoted the marker. The check on the author type finds the comments of the
Depot CI app and the older comments of `github-actions[bot]`.

### fix(revision.city): read a findings list that ends with stray braces

A review model can send its findings list as JSON text and then close that text with the braces of
the object around it, for example `[{...}]}`. The parse failed, so the chunk review failed and the
check went red with no finding. A JSON array never ends with a brace, so the reviewer now removes
trailing braces and white space from the text before it parses the list.

### fix(revision.city): retry the guide read before reviewing without guides

The review reads the `AGENTS.md` guides at the base commit for each reviewer's prompt. Before, any
failure of that read, such as one GitHub 502, gave a review without the guides at once. Because the
guides are part of the key for saved chunk reviews, each chunk then missed its saved result, and the
run paid for it again. Now a failure before the last attempt of the `read pull request and guides`
step throws, so the Workflow retries the step. Only the last attempt reviews without guides, as
before.

### fix(revision.city): show the address of links in posted model text

The reviewer cleans mentions, issue references, HTML, and suggestions out of the model text that it
posts. Markdown links and images went through as they were. So a pull request's author could steer
the model to show an image, or a link whose text hides where it goes, under the app's name. The
cleaner now puts a zero-width space after the `]` of `](` and `]:`. A link or an image then shows as
its Markdown source, and its address stays a plain link that shows its host. Bare addresses do not
change.

### fix(revision.city): keep the newest run when the summary comment is full

When the summary comment got longer than GitHub accepts, the app cut the end of the text. Then the
newest run lost findings, or the comment did not show it, and the run count and the total cost
stopped at the old values. Now a cut removes text from the oldest runs first: the details of each
run, then the findings of each older run, then each older run. The newest run loses findings only
when it alone is too long for the comment. A hidden line in the header holds the number and the cost
of the removed runs, so the header still counts each run and its cost. A finding title with a
Unicode line or paragraph separator now stays on one line, so the summary comment reads it back as a
finding.

### fix(revision.city): turn off Version URLs on the production worker

The production worker config set `preview_urls = true`, so each production version could also answer
on its own public workers.dev host. Those hosts use the production database, Workflow, and secrets,
but they are outside the revision.city zone and its rate limit rule, and Workers Logs does not
record them. Nothing uses them: since August, previews upload as versions of the dev worker, which
keeps its own `preview_urls = true`. The config now sets `false`, so the next production deploy
turns off Version URLs and any `pr-<N>` aliases that remain from before August. The old comment said
that previews need the setting; the new comment says why the key stays and is `false`.

### fix(web-apps): pass deploy build variables through turbo

The deploy build sets `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_AUTH_TOKEN` and
`STANDARD_SITE_RESOLVE`. But turbo runs the build in strict environment mode, and it removes each
variable that the task does not declare. Thus the Astro apps did not upload their Sentry source
maps, and djf.io posts had no standard.site document link. The `build` task now declares the three
plain values in `env`, so they are in the cache hash. It declares the token in `passThroughEnv`, so
the token reaches the build but stays out of the hash.

### perf(revision.city): load the portable diff worker and preload three grammars

The diffs highlight workers now load the portable worker build of `@pierre/diffs`. The standard
build pulled every shiki grammar into the worker script, but a worker cannot load a grammar. The
worker script drops from 10.9 MB to 1.35 MB (about 0.5 MB gzip), and the Worker upload drops by
about 9 MiB, because the server build keeps a copy of the script. The worker pool and the main
thread highlighter now preload only `rust`, `tsx` and `typescript`; other languages load when a file
needs them. The local smoke check now fails when a client asset is larger than 2 MiB.

### perf(revision.city): redraw only the Symbols files that changed

The Symbols tab fills in one file at a time, and each result drew every file that the list already
showed again. On a large diff the total work grew with the square of the file count. Each file
section is now memoized, so a new result no longer draws the files that did not change. A new test
adds a second file and expects the first file's rows to draw only once.

### refactor(revision.city): move the settings switch from Radix to Ark UI

The display settings switches (Backgrounds, Line numbers, Word wrap) now use the Ark UI switch, and

### test(revision.city): pin the diff route's host allowlist

The diff route tests now have a table of 18 inputs that the route must reject with a 400 and no
upstream fetch. The rows cover unknown and look-alike hosts and domains, plain http, a port, a user

parser did not read them, so the review lost one medium and one low finding to "No findings list"
failures. A `findings` string that parses as a JSON array now counts as the list, in a text answer
and in a `submit_answer` call. The list also counts under the key `finding`, and under the key
`answer` as an object or a JSON string. A `findings` string that is not a JSON array still fails,
with the reason "the findings are a string that is not a JSON array".

### fix(revision.city): ask for the answer without reasoning after a cut reply

On #938, 3 of 24 chunk reviews failed with an empty answer. Each one used all 32,000 output tokens
to reason, two times, because a cut review ran again from the start and reasoned as long the second
time. Now, when the output token limit cuts a reply, the review does not run again. It makes one
more call on the same conversation with the reasoning off and `submit_answer` as the only tool, so
the model answers from the files that it read before the cut. An answer without reasoning is short,
so this call costs less than a second run. The `model call` log events show `reasoningEffort` as
`none` for this call, and they no longer have a `run` field.

### feat(revision.city): show the cost of each chunk review in a table

The "Cost per chunk review" section of the check run is now a table with columns for cost, chunk,
reviewer, prompt tokens, and completion tokens. A total row is the first row, so that a cut of a
long list keeps it. Token counts have thousands separators. Paths in the table are plain text with
each punctuation character escaped, so a path with a backslash before a "|" cannot split its row.

### feat(revision.city): keep one summary comment on each pull request

Each review now adds a section to one Revision City comment on the pull request, and edits that
comment in place. A section shows the commit, the findings, and the cost table of its run. The top
of the comment shows the number of runs and their total cost. When the comment gets too long for
GitHub, the oldest runs lose their details first and keep their heading and cost. A failed comment
update only logs a warning and does not fail the review. Each section holds the id of its check run,
so a retry after a lost response does not add the run again. A lock in D1 (the
`summary_comment_locks` table, with a 60-second lease) lets one run at a time edit the comment.
While another run holds it, the step tries again later.

### fix(revision.city): accept a lone finding and say why an answer does not parse

On #915's review, 2 of 8 failed chunk reviews were one real finding without the
`{"findings": [...]}` list around it. That finding now counts as a list of one, unless the answer
has a JSON syntax error, which the token limit usually causes. A failed answer now says more than
"No findings list": it says when the answer is a tool call or a message written as text, or an empty
object. A `submit_answer` call that the token limit cuts now gets the second run that a cut text
answer gets, and fails as "Answer cut at the output token limit" after it.

### fix(revision.city): give the review answer as a submit_answer tool call

After #894, 28 of 105 chunk reviews on #910 failed, and only 1 of them at the output token cap. 85
of 100 answers came on the last round, after the tools went off. There the model often wrote the
tool calls that it still wanted as text, which does not parse. A reviewer with tools now gives its
answer as the arguments of a `submit_answer` tool call. On the last round, `submit_answer` is the
only tool, and the request makes the model call it. A text answer still counts, for a provider that
does not support a required tool call. The system prompt changes, so the first review after this
change pays again for each chunk review.
