# 2026-10-10 -- Saved results move to drizzle, and a local review

## Session summary

David asked to use drizzle for the database, and whether the engine needs pi or the Claude Agent
SDK. This session moved the saved-result store to drizzle and answered the runtime question in the
project thread. Later, David asked for a review of the PR with three review skills, run in this
session instead of Warden. This session then fixed the findings that it confirmed.

## Work completed

- `src/reviews/lib/schema.ts` defines the `chunk_reviews` table with drizzle. `mise run db:generate`
  writes its migrations into `drizzle/`, the same layout as monicandavid.com. The first migration
  replaces `migrations/0001-chunk-reviews.sql`.
- `createSqliteChunkReviewStore` takes a drizzle database. In phase 2, the worker passes
  `drizzle(env.DB)`. Its tests use an in-memory SQLite database (`node:sqlite`) with the real
  migrations applied.
- David asked for a review with the built-in `code-review` and `security-review` skills and this
  repository's `comment-review` skill. They ran with Claude in this session instead of Warden.
  Security found nothing at medium or above. The fixes from the other two:
  - A finding range that crosses a hunk gap, leaves the chunk, or ends before it starts is cut to
    its first line, and its suggestion is dropped.
  - Duplicate findings are removed only when they end on the same line, so a wide range no longer
    hides findings inside it.
  - One malformed finding no longer drops the valid findings in the same answer. The chunk still
    counts as failed.
  - A store failure does not fail a review, and an answer with no content keeps its billed usage.
  - The engine does not send a slice of only removed lines to the reviewers, because findings anchor
    only to lines of the new file.
  - `isAtLeast` and `mapWithConcurrency` take named arguments, and several comments and docs now
    match the code.

## Decisions

- Use drizzle for D1, the same as monicandavid.com (David asked for it).
- Dedupe findings only when they end on the same line. Dedupe on any overlap lost real findings
  inside a wide range, which is worse than two comments near each other.

## Next steps

- Phase 2, with one proposed change. Keep the direct OpenRouter calls, without pi or the Claude
  Agent SDK. The Claude Agent SDK needs a local filesystem and shell, and a Worker has neither.
- Give each reviewer a small tool loop. Its tools read a file and list a directory through the
  GitHub API, at the PR's head commit. A saved chunk review then records the files its reviewer
  read, and stays valid while the chunk and those files do not change.

## Blockers / open questions
