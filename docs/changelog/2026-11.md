# 2026-11

## 2026-11-02

### chore(warden): run the CI review only when a PR gets the Warden label

Warden no longer reviews each PR on open and on each push. `ci-warden.yml` now triggers only on
`labeled` events, and its job runs only for the `Warden` label. Add the label to a PR, draft or bot
PR included, to review its current head. Remove and add it again to run again. `warden.toml`'s
triggers use the same filter (`actions = ["labeled"]`, `labels = ["Warden"]`). The dispatch path for
branches does not change.

revision.city reviews each push from its GitHub App, so Warden is now only for a second opinion.
CONTRIBUTING's code review section now says the same.

## 2026-11-01

### chore(tooling): move the Biome config schemas to 2.6.3 and let Renovate keep them in step

The repo pins `@biomejs/biome` 2.6.3, but every Biome config still named the 2.5.14 schema in its
`$schema` URL. Each `biome check` and `biome format` run printed a "configuration schema version
does not match" notice for each app. `biome migrate --write`, run from `workspaces/web-apps` with
the pinned CLI, changed the URLs and no other setting: version 2.6 needs no other config migration.
The migrate also removed the trailing commas from the two `.jsonc` files, so oxfmt put them back.
The two joy-of-react configs got the same URL change by hand, because `biome migrate` cannot load
them. They extend the repo-root `biome.jsonc`, which no longer exists.

The URLs fell behind the CLI before: a change in 2026-09 moved them from 2.5.10 to 2.5.14. A new
regex custom manager in `.github/renovate.json` now reads each Biome config's schema URL as an
`@biomejs/biome` dependency. So the "biome packages" group moves the URLs in the same PR as the CLI
pins. The manager runs no commands, so `RENOVATE_ALLOWED_COMMANDS` does not change.

### docs(web-apps): correct the bunfig override notes

The comment in `workspaces/web-apps/bunfig.toml` that explains the root `overrides` had two bullets
that no longer matched `workspaces/web-apps/package.json`. This change deletes the
`@distilled.cloud` bullet, because the root `package.json` has no `@distilled.cloud/*` overrides.
Without them, `bun.lock` holds one copy of each `@distilled.cloud/*` package. The rolldown bullet
gave the version as 1.2.1, but the override is 1.2.15. The bullet now has no version numbers. It
says that the override makes every consumer use one rolldown version, and that a change needs the
djf.io e2e tests with `CI=1`.

The `/diffs` home page no longer ends with the "Powered by Pierre's open source FileTree and

### feat(revision.city): check each finding before it posts

A second tool loop now checks each finding that a chunk review would post, at most 5 for each chunk
review. The check reads the code that the finding depends on and must quote the lines that show the
problem. A confirmed finding gets that proof in its comment. A rejected finding is not posted, and
the check run lists it under "Not checked, so not posted". When a check fails or does not parse, the
review does not post its finding. The check run lists the chunk review as failed, and the app does
not save it, so the next run checks it again. The saved result key version is now 2, so the first
review after this change pays again for each chunk review.

### fix(alchemy-state-viewer): hold @ark-ui/svelte at 5.24.3

The lock file maintenance run moved `@ark-ui/svelte` from 5.24.3 to 5.25.0, and the
alchemy-state-viewer build and typecheck failed. The 5.25.0 package keeps the `$lib/...` imports of
its source in the published `dist` instead of relative paths. SvelteKit 3 removed `$lib`, so
`vite build` stopped with `module_removed_lib`. svelte-check also lost the prop types, so `children`
was not a known prop of `JsonTreeView.Root`. The two apps that depend on the package
(alchemy-state-viewer and monicandavid.com) now pin it to exactly 5.24.3. A Renovate rule holds it
below 5.25.0 until a release uses relative imports again.

### fix(f311x): move alchemy to 2.0.0-beta.84 and its new provider packages

alchemy 2.0.0-beta.84 moved the Cloudflare and GitHub providers out of the `alchemy` package into
`@alchemy.run/cloudflare` and `@alchemy.run/github`. The Renovate alchemy bump did not add them, so
the f311x typecheck failed: `alchemy/Cloudflare` and `alchemy/GitHub` no longer resolve. f311x now
depends on both packages at 2.0.0-beta.84, and `alchemy.run.ts` and `github.ts` import from them.
The Renovate alchemy group now includes `@alchemy.run/**`, so these packages move with alchemy.

The same Renovate PR moved effect from 4.0.6 to 4.1.0. effect 4.1 removed the top-level
`effect/Crypto` module, but alchemy 2.0.0-beta.84 still imports it. Thus `alchemy deploy` cannot
load the f311x stacks on effect 4.1. tsc does not report this, because `skipLibCheck` hides the
missing module. effect and `@effect/platform-node` stay at 4.0.6. A new Renovate rule holds effect
and `@effect/**` below 4.1 until an alchemy release supports it.

`@alchemy.run/cloudflare` also depends on `@effect/sql-d1` `^4.0.5`, which resolved to 4.1.1. That
release needs effect `^4.1.1` as its peer. A new workspace override pins `@effect/sql-d1` at 4.0.6,
so the tree keeps one effect copy.
