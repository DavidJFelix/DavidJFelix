# 2026-08-01 -- Feasibility spike

## Session summary

Ran the full mechanical feasibility spike for moving the apps from pnpm to bun (1.3.11). Method:
copied each app to a scratch tree without `node_modules`, then ran `bun install`, `bun run build`,
and `bun run test` against the copy so the repo tree stayed untouched.

## Work completed

- All 12 apps verified green under bun: install, build, and unit tests (vitest with coverage gates).
  Families covered: Astro x4, TanStack Start x4, SvelteKit x2, Nuxt, Vite SPA.
- Playwright e2e on davidjfelix.com: 8 passed including the visual baseline, `wrangler dev` booting
  from the bun-installed tree; `bun x wrangler deploy --dry-run` clean.
- Proved lockfile migration is faithful (pnpm-lock resolutions preserved, overrides carried into
  `bun.lock`), `prepare` scripts run, and `--frozen-lockfile` works even before `bun.lock` is
  committed.
- Probed the sharp edges: `trustedDependencies` replaces bun's default trust list; `bunfig.toml` is
  not inherited from parent directories; `minimumReleaseAge` is enforced when set;
  `bun pm trust @sentry/cli` fetches the sentry-cli binary.
- Measured `bun test` against the existing suites: pure-logic files pass unmodified, but
  `vi.stubGlobal`/`vi.resetModules`, the jsdom environment, and branch coverage are missing --
  vitest stays.
- Wrote the findings and the mechanical inventory into [plan.md](./plan.md).

## Decisions made

- Bun is the app package manager and script runner (tooling standard amended).
- Vitest stays the test runner, invoked via `bun run test` -- `bun test` is not used.

## Rebase over the theme extraction (2026-08-02)

Main landed `packages/theme` (#396, a `file:` dependency consumed by 8 apps) after the migration was
authored, so the branch was rebased and the new surface migrated the same way: `bun.lock` via
lockfile migration, `trustedDependencies: ["esbuild"]`, `bunfig.toml`, mise tasks, and
`ci-theme.yml` moved to bun; the 8 consuming apps' lockfiles regenerated with the `file:` dep. Two
findings from the rebase:

- Main's session-start hook referenced `appsDir` after removing its definition (a latent crash in
  step 4); the conflict resolution restores a working reference.
- bun installs a `file:` dependency's devDependencies where pnpm pack-installed without them, so
  consuming apps carry a nested copy of the theme package's dev tooling (react included). Verified
  harmless -- all four React consumers (ravrun, f311x, forzamonica.com, startchi.com) pass their
  full Playwright e2e suites against built apps, f311x including SSR through workerd, and bundles
  carry a single React -- but it is the first thing to check if a theme consumer misbehaves.
