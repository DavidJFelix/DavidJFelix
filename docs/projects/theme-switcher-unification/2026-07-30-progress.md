# 2026-07-30 Progress

Session: post-merge follow-up. PR 1 (theme parity, #390) merged; the theme storage schema moved to
zod 4 as its own PR.

## Work completed

- Replaced every hand-rolled theme-mode validator with the shared zod 4 schema
  (`z.catch(z.enum(['light', 'dark', 'system']), 'system')`, imported from `zod/mini`): the four
  TanStack `theme-controller.ts` copies, revision.city's persistence adapter, pkg.dog's
  `parseThemePreference`, and the four Astro toggle scripts. `ThemeMode` types are inferred from the
  schema.
- `zod@^4.4.3` added as a dependency to the nine apps that parse the storage value; the SvelteKit
  apps stay zod-free (mode-watcher validates internally with the same semantics).

## Decisions made

- `zod/mini` over classic zod for the functional, tree-shakable API: the schema lands in client
  bundles (including static Astro pages), so bundle cost had to stay proportional to the schema
  used.
- The pre-paint inline bootstrap scripts keep their literal checks (they cannot import anything);
  each is commented as the schema's compiled twin so drift is caught in review.
