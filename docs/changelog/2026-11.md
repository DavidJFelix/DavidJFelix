# 2026-11

## 2026-11-03

### feat(revision.city): show resolved findings in the summary comment

Each run section of the summary comment now lists its findings above the collapsed details, and the
details no longer repeat them. A finding shows struck through and marked resolved when a user who
can push resolved every thread of that finding, also outdated threads. Its run cost still counts in
the total. Each edit of the comment, at the end of a run, shows the current state for the findings
of every run.

### fix(alchemy-state-viewer): drop the @ark-ui/svelte hold

`@ark-ui/svelte` 5.25.1 uses relative imports in its `dist` again, so the alchemy-state-viewer build
and typecheck pass on it. This change removes the Renovate rule that held the package below 5.25.0.
alchemy-state-viewer goes back to a caret range, `^5.25.1`. The range starts at 5.25.1 because
5.25.0 is still on npm with the `$lib/...` imports. monicandavid.com listed the package but did not
import it, so this change removes it from that app.

### fix(revision.city): read findings sent as a JSON string or under a misspelled key

On #938's review, the review model sent two answers with the findings list as a JSON string. The
parser did not read them, so the review lost one medium and one low finding to "No findings list"
failures. A `findings` string that parses as a JSON array now counts as the list, in a text answer
and in a `submit_answer` call. The list also counts under the key `finding`, and under the key
`answer` as an object or a JSON string. A `findings` string that is not a JSON array still fails,
with the reason "the findings are a string that is not a JSON array".

### fix(revision.city): ask for the answer without reasoning after a cut reply

On #938, 3 of 24 chunk reviews failed with an empty answer. Each one used all 32,000 output tokens
to reason, two times, because a cut review ran again from the start and reasoned as long the second
time. Now, when the output token limit cuts a reply, the review does not run again. It makes one
more call on the same conversation with the reasoning off and `submit_answer` as the only tool, so
the model answers from the files that it read before the cut. An answer without reasoning is short,
so this call costs less than a second run. The `model call` log events show `reasoningEffort` as
`none` for this call, and they no longer have a `run` field.

## 2026-11-02

### chore(warden): run the CI review only when a PR gets the Warden label

Warden no longer reviews each PR on open and on each push. `ci-warden.yml` now triggers only on
`labeled` events, and its job runs only for the `Warden` label. Add the label to a PR, draft or bot
PR included, to review its current head. Remove and add it again to run again. `warden.toml`'s
triggers use the same filter (`actions = ["labeled"]`, `labels = ["Warden"]`). The dispatch path for
branches does not change.

revision.city reviews each push from its GitHub App, so Warden is now only for a second opinion.
CONTRIBUTING's code review section now says the same.

### feat(revision.city): show the cost of each chunk review in a table

The "Cost per chunk review" section of the check run is now a table with columns for cost, chunk,
reviewer, prompt tokens, and completion tokens. A total row is the first row, so that a cut of a
long list keeps it. Token counts have thousands separators. Paths in the table are plain text with
each punctuation character escaped, so a path with a backslash before a "|" cannot split its row.

### feat(revision.city): keep one summary comment on each pull request

Each review now adds a section to one Revision City comment on the pull request, and edits that
comment in place. A section shows the commit, the findings, and the cost table of its run. The top
of the comment shows the number of runs and their total cost. When the comment gets too long for
GitHub, the oldest runs lose their details first and keep their heading and cost. A failed comment
update only logs a warning and does not fail the review. Each section holds the id of its check run,
so a retry after a lost response does not add the run again. A lock in D1 (the
`summary_comment_locks` table, with a 60-second lease) lets one run at a time edit the comment.
While another run holds it, the step tries again later.

### fix(djf.io): clarity edits to the coder post draft

Applied the accepted clarity edits to the "Coder, Programmer, Developer, or Engineer?" draft. Long
sentences are split, unclear subjects are named, and the salary claim now says what the author saw
in job postings. The draft is not published yet.

### fix(revision.city): accept a lone finding and say why an answer does not parse

On #915's review, 2 of 8 failed chunk reviews were one real finding without the
`{"findings": [...]}` list around it. That finding now counts as a list of one, unless the answer
has a JSON syntax error, which the token limit usually causes. A failed answer now says more than
"No findings list": it says when the answer is a tool call or a message written as text, or an empty
object. A `submit_answer` call that the token limit cuts now gets the second run that a cut text
answer gets, and fails as "Answer cut at the output token limit" after it.

### fix(revision.city): give the review answer as a submit_answer tool call

After #894, 28 of 105 chunk reviews on #910 failed, and only 1 of them at the output token cap. 85
of 100 answers came on the last round, after the tools went off. There the model often wrote the
tool calls that it still wanted as text, which does not parse. A reviewer with tools now gives its
answer as the arguments of a `submit_answer` tool call. On the last round, `submit_answer` is the
only tool, and the request makes the model call it. A text answer still counts, for a provider that
does not support a required tool call. The system prompt changes, so the first review after this
change pays again for each chunk review.

## 2026-11-01

### chore(tooling): move the Biome config schemas to 2.6.3 and let Renovate keep them in step

The repo pins `@biomejs/biome` 2.6.3, but every Biome config still named the 2.5.14 schema in its
`$schema` URL. Each `biome check` and `biome format` run printed a "configuration schema version
does not match" notice for each app. `biome migrate --write`, run from `workspaces/web-apps` with
the pinned CLI, changed the URLs and no other setting: version 2.6 needs no other config migration.
The migrate also removed the trailing commas from the two `.jsonc` files, so oxfmt put them back.
The two joy-of-react configs got the same URL change by hand, because `biome migrate` cannot load
them. They extend the repo-root `biome.jsonc`, which no longer exists.

The URLs fell behind the CLI before: a change in 2026-09 moved them from 2.5.10 to 2.5.14. A new
regex custom manager in `.github/renovate.json` now reads each Biome config's schema URL as an
`@biomejs/biome` dependency. So the "biome packages" group moves the URLs in the same PR as the CLI
pins. The manager runs no commands, so `RENOVATE_ALLOWED_COMMANDS` does not change.

### docs(web-apps): correct the bunfig override notes

The comment in `workspaces/web-apps/bunfig.toml` that explains the root `overrides` had two bullets
that no longer matched `workspaces/web-apps/package.json`. This change deletes the
`@distilled.cloud` bullet, because the root `package.json` has no `@distilled.cloud/*` overrides.
Without them, `bun.lock` holds one copy of each `@distilled.cloud/*` package. The rolldown bullet
gave the version as 1.2.1, but the override is 1.2.15. The bullet now has no version numbers. It
says that the override makes every consumer use one rolldown version, and that a change needs the
djf.io e2e tests with `CI=1`.

### feat(djf.io): add draft essay on software role names

Added a draft essay, "Coder, Programmer, Developer, or Engineer?", to `src/drafts/`. The essay
compares the four names for the job, argues that the name we use shows respect for the work, and
looks at how AI can change each role. The draft is not published yet.

### feat(revision.city): remove the "Powered by" credits from the diffs pages

The `/diffs` home page no longer ends with the "Powered by Pierre's open source FileTree and
CodeView components" note, and the diff viewer sidebar no longer shows the "Powered by Diffs and
Trees" row under the worker pool status.

### feat(revision.city): check each finding before it posts

A second tool loop now checks each finding that a chunk review would post, at most 5 for each chunk
review. The check reads the code that the finding depends on and must quote the lines that show the
problem. A confirmed finding gets that proof in its comment. A rejected finding is not posted, and
the check run lists it under "Not checked, so not posted". When a check fails or does not parse, the
review does not post its finding. The check run lists the chunk review as failed, and the app does
not save it, so the next run checks it again. The saved result key version is now 2, so the first
review after this change pays again for each chunk review.

### fix(alchemy-state-viewer): hold @ark-ui/svelte at 5.24.3

The lock file maintenance run moved `@ark-ui/svelte` from 5.24.3 to 5.25.0, and the
alchemy-state-viewer build and typecheck failed. The 5.25.0 package keeps the `$lib/...` imports of
its source in the published `dist` instead of relative paths. SvelteKit 3 removed `$lib`, so
`vite build` stopped with `module_removed_lib`. svelte-check also lost the prop types, so `children`
was not a known prop of `JsonTreeView.Root`. The two apps that depend on the package
(alchemy-state-viewer and monicandavid.com) now pin it to exactly 5.24.3. A Renovate rule holds it
below 5.25.0 until a release uses relative imports again.

### fix(f311x): move alchemy to 2.0.0-beta.84 and its new provider packages

alchemy 2.0.0-beta.84 moved the Cloudflare and GitHub providers out of the `alchemy` package into
`@alchemy.run/cloudflare` and `@alchemy.run/github`. The Renovate alchemy bump did not add them, so
the f311x typecheck failed: `alchemy/Cloudflare` and `alchemy/GitHub` no longer resolve. f311x now
depends on both packages at 2.0.0-beta.84, and `alchemy.run.ts` and `github.ts` import from them.
The Renovate alchemy group now includes `@alchemy.run/**`, so these packages move with alchemy.

The same Renovate PR moved effect from 4.0.6 to 4.1.0. effect 4.1 removed the top-level
`effect/Crypto` module, but alchemy 2.0.0-beta.84 still imports it. Thus `alchemy deploy` cannot
load the f311x stacks on effect 4.1. tsc does not report this, because `skipLibCheck` hides the
missing module. effect and `@effect/platform-node` stay at 4.0.6. A new Renovate rule holds effect
and `@effect/**` below 4.1 until an alchemy release supports it.

`@alchemy.run/cloudflare` also depends on `@effect/sql-d1` `^4.0.5`, which resolved to 4.1.1. That
release needs effect `^4.1.1` as its peer. A new workspace override pins `@effect/sql-d1` at 4.0.6,
so the tree keeps one effect copy.

### fix(joy-of-react): point the Biome configs at the web-apps workspace config

The Biome configs of the two Joy of React projects extended `../../../biome.jsonc`, the repo-root
config that the Turborepo consolidation moved to `workspaces/web-apps/biome.jsonc`. Biome could not
load either config, so the `lint` and `format` scripts of the projects failed. Each project now has
a `biome.jsonc` root config that extends `../../web-apps/biome.jsonc`. The old root config had the
same Biome rules, so the projects get the rules they had before the move. That rule set is not the
full Biome set: it keeps only the rules that oxlint does not have, and the `lint` script of each
project also runs oxlint. The configs now use JSONC, as the configuration style guide requires.

The web-apps config lets Biome format only `.astro` and `.svelte` files, because oxfmt formats the
other files there. These projects do not use oxfmt, so each config sets the Biome formatter to its
JS, JSX, CSS, and JSON files. Now `format` and `lint` check the project sources. The sources already
had the correct format, so no file changed.
